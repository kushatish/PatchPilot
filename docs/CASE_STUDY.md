# Historical Click bug: unsafe filename display

## Source and scope

Repository: `pallets/click`.
Issue: [#2395](https://github.com/pallets/click/issues/2395).
Historical tag: `8.1.3`.
Resolved commit: `9c6f4c8e1bb8670ce827c98559f57f6ee5935cd0`.

The issue describes filenames with bytes that cannot be decoded as ordinary UTF-8. Click's display formatting leaves surrogate characters in the resulting string, causing an encoding error when printing. The issue is already closed; this is a historical reproduction, not an unresolved issue to submit upstream.

## Independent reproduction

`benchmarks/click_reproducer.py` tests both a string containing a surrogate and an undecodable byte filename. It checks that the formatted result can be encoded for display. These tests were authored independently for this case study, not generated by Claude.

On the tagged source, both tests failed with `UnicodeEncodeError` (pytest exit 1). The captured output and resolved commit are recorded in `click-baseline.json`.

To reproduce on a non-Windows machine with Git and the project dependencies:

```bash
git clone --depth 1 --branch 8.1.3 https://github.com/pallets/click.git /tmp/patchpilot-click-813
PYTHONPATH=/tmp/patchpilot-click-813/src python -m pytest -q benchmarks/click_reproducer.py
```

Expected: **2 failed**. The failure is intentional evidence of the historical bug.
